# Проект NTrail backend

Frontend лежит в отдельном репозитории 

Текущая версия репозитория является полноценным docker-compose проектом

## Запуск с сервера (подразумевается доступ по ssh)
Сначала понадобится создать ssh ключ
```shell
# Переходим в папку с ssh ключами
cd ~/.ssh 
# Генерируем пару ключей - секретный и приватный
ssh-keygen -f ~/.ssh/github.com
# Добавляем config для использования github.com без пароля
echo "Host github.com
        Hostname github.com
        IdentityFile ~/.ssh/github.com" > ~/.ssh/config
```
Добавить в аккаунт на [github](https://github.com/settings/keys) публичный ключ
```shell
cat ~/.ssh/github.com.pub
```

**На чистом ubuntu сервере выполнить**
```shell
apt update -y
apt install -y git
cd /root
git clone git@github.com:fivol/ntrail-backend.git
cd ntrail-backend
./start.sh
```

**Обновление версии из github:master С СЕРВЕРА**
```shell
cd /root
cd ntrail-backend
./update.sh
```

Ручной старт
```shell
docker-compose build
docker-compose up -d
```
`-d` для запуска в background

Перезапуск
```shell
docker-compose restart
```

## Push последних изменений на сервер
*То, что сейчас в ветке master в удаленном репозитории будет загружено и запущено на удаленной машине.
Предполагается, что после выполнения команды `ssh root@<ip>` будет произведен заход на сервер, если это не так
необходимо прописать данные для подключения (пароль или публичный ключ) в папку ~/.ssh
[Вот инструкция](https://community.vscale.io/hc/ru/community/posts/207745269-%D0%9A%D0%B0%D0%BA-%D1%81%D0%B3%D0%B5%D0%BD%D0%B5%D1%80%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D1%82%D1%8C-SSH-%D0%BA%D0%BB%D1%8E%D1%87-%D0%B4%D0%BB%D1%8F-%D0%B4%D0%BE%D1%81%D1%82%D1%83%D0%BF%D0%B0-%D0%BD%D0%B0-%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80)*
[или эта](https://www.ssh.com/ssh/keygen/)

```shell
./upload.sh root@1.2.3.4
```
Вместо "root@1.2.3.4" следует указать адрес для подключения по ssh

**Внимание:** будут загружены и запущен только закомиченные и запушенные на github в ветку мастер изменения

## Соглашения по ведению проекта
1. Любые правки, фичи, изменения создаются в новой ветке
1. Каждая существующая ветка должна быть описана в этом README
1. Разработка python части ведется в виртуальном окружении app/venv
1. Используемые пакеты должны быть отражены в requirements.txt
`pip freeze > requirements.txt`
1. **Чистый понятный код**, исправляем все замечания среды разработки, следуем стандартам *pep8*
1. Разработка ведется в **clion**, в качестве проекта следует открывать корневую папку - эту


## Структура проекта

```shell
        requirements.txt

        certs 
            certificate.crt
            certificate.key
```


## Описание веток
*Некоторых из них может не быть, но нужно понимать назначение при создании веток такими названиями!*
1. **master** 
Содержит продакшн версию приложения, загрузив на сервер или локально 
его всегда можно собрать используя команды выше, все правки из других веток 
после тестирования попадают сюда. **Делать изменения в master напрямую нельзя, 
   только сливать ветки и исправлять конфликты**
1. **dev**
Устоявшееся название для рабочей ветки с общими исправлениями, заменяет кодинг в 
   мастере
1. **test**
Совершенно экспериментальный функционал, сделанный из любопытства или проверки гипотезы
