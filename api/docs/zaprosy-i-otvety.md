# Запросы и ответы

## Получение токена для авторизации

На данный момент авторизация производится через ВК, необходимо иметь аккаунт. Для получения перейдите по [ссылке](https://oauth.vk.com/authorize?client_id=7898476&redirect_uri=http://localhost:8000/verify/&scope=0&response_type=code) и скопируйте его. При потере можно заново получить тот же токен по той же ссылке

## Описание параметров некоторых GET запросов

### verbose

1. **simple** - выводить каждое поле напрямую, в формате ключ: значение. Значение может быть получено разными способами, главное - оно должно соответствовать описанию. Например возраст указан на странице, но алгоритмы решают, что он некорректный и значение перезаписывается из значений возрастов друзей
2. **normal** - каждое поле может содержать дополнительную информацию и выводится в словаре, со значением по ключу value \(см пример ниже\). Таким образом может быть добавлено мета свойство confidence - уверенность в ответе, source - источник: страница пользователя, анализ друзей, групп и т.д.
3. **detail** - добавляется еще больше данных. Используется для более глубокого анализа результатов. Если есть несколько ответов разной степени точности, в этом режиме выведутся все из них с уточненными мета свойствами, например confidence. В normal или simple режимах, был бы показан только один лучший вариант

**Пример:**

```text
# verbose: simple
{
    "name": "Petr", 
    "age": 11
}
# verbose: normal
{
    "name": {
        "value": "Petr"
    },
    "age": {
        "value": 11,
        "confidence": 0.58
    }
}
# verbose: detail
{
    "school": [
        {
            "value": "School 91",
            "confidence": 0.79,
            "source": "page"
        },
        {
            "value": "Shool 45",
            "confidence": 0.38,
            "source": "friends"
        }
    ]
}
```

### options

Перечисленные в массиве значения options добавляют ряд полей в ответ. Подробно в swagger для каждого запроса

## Формат ответа

В соответствии с options в ответе будут представлены разные поля. Если значение одного из полей ну указано или не проходит проверку на корректность, оно не будет представлено в ответе. Это важно учитывать при обработке результатов запроса

### Как протестировать и выполнить несколько запросов?

1. Переходим в [Swagger](http://127.0.0.1:8000/docs)
2. Открываем интересующий запрос
3. Нажимаем кнопку **Try it out**
4. Заполняем все необходимые параметры через интерфейс
5. Нажимаем _**execute**_

## Лимиты и цены

Изначально у вас есть резерв бесплатных запросов, действует ограничение на количество в сутки и частоту. У запросов разная сложность, так что каждому присвоен вес. Именно единицы стоимости расходуются на каждый запрос в соответствии с его весом

### Вес запросов

1. Уровень basic: 1
2. Уровень connections: 3
3. Уровень friends: 2
